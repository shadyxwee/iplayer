# Agent Instructions & Workflow Protocol

## Task Execution Workflow
1. Read Context First: Review existing feature modules under `/lib/src/features` and Rust FFI APIs under `/rust/src/api` before generating new code.
2. Maintain Layer Separation:
   - UI code must NOT parse raw M3U streams or manually construct HTTP header signatures for Stalker portals.
   - Core API drivers and stateful connection engines belong inside the Rust workspace (`/rust`).
   - State management (Riverpod/Bloc) must call clean FFI functions generated by `flutter_rust_bridge`.
3. Test Focus Navigation: When creating any Flutter view or widget, ensure D-Pad accessibility by testing that `FocusNode` hooks and directional key bindings operate as expected.

## Error Handling & Reliability Rules
- Media Playback Errors: Video streams can drop unexpectedly. Player state controllers must gracefully handle buffer timeouts, auto-retry, and display human-readable status overlays rather than throwing unhandled exceptions.
- Stalker Session Expiry: When a MAC portal returns an unauthorized status code (e.g., `401` or expired token signature), auto-trigger the Stalker re-handshake routine transparently.
- Data Limits: Assume playlists will contain 100,000+ entries. Never load complete channel arrays into UI memory at once—fetch pages or query SQLite database views asynchronously.
